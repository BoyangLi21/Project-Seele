# Project SEELE 地图微改短流程

本规范合并 Claude 2026-08-08 交接中的实测加速建议与 GPT-5.6 Pro 的空间孪生方案。
它用于已有存档的细微修复；不是自动生成新设施的授权。

## 三条绝对规则

1. `git log` 和当前权威存档是基线；现阶段唯一权威世界是
   `SEELE_S20_RECOVERY_R28`。
2. `tools/query_blocks.py` 是唯一的存档方块读取入口；不得再复制区块、调色板和
   Anvil 解码代码。
3. 每一个拟写坐标都必须能回答“实测旧状态是什么、为什么允许改、怎么还原”。

空气、可站立面、开放组件、碰撞检测通过，都不等于房间、通道或建设许可。未知区域
一律 `HOLD`。

## 地点卡

一轮只处理一个地点卡：

```json
{
  "id": "PLACE_ID",
  "world": "SEELE_S20_RECOVERY_R28",
  "anchor": [0, 0, 0],
  "facing": "north|south|east|west",
  "purpose": "人类确认的用途",
  "in": {"pos": [0, 0, 0], "normal": [0, 0, 0]},
  "out": {"pos": [0, 0, 0], "normal": [0, 0, 0]},
  "neverTouch": [],
  "mustShow": [],
  "mustNotShow": [],
  "reference": [],
  "acceptanceCamera": []
}
```

地点、朝向、用途、入口或出口任一不确定时，停止并输出证据，不得猜。

## 5–10 分钟局部闭环

1. **0–1 分钟：地点卡。** 把真人自然语言、F3 坐标、面向和截图落成卡片。
2. **1–2 分钟：只读实测。** 用 `query_blocks.py` 读局部 box；先画 ASCII 平面或剖面。
3. **2–4 分钟：空间证据。** 仅在 ASCII 仍不足时，调用
   `survey_facility_target.py` 生成入口/出口内外双向视图、中心线双向视图、横纵剖面、
   45° 视图和局部 GLB。图上必须有坐标、北箭头、Y 标尺、端口法向和材质图例。
4. **4–6 分钟：唯一 ghost。** 只生成一个候选，不并行生成多个世界让真人挑。
5. **6–7 分钟：可逆差异。** 导出精确 `positiveEditMask`、逐格旧状态前置条件、
   `forwardPatch` 和 `inversePatch`。
6. **7–9 分钟：视觉异议。** Claude/视觉模型只指出走向、遮挡、比例或原作约束冲突；
   不写世界、不改事实源。
7. **9–10 分钟：真人裁决。** 批准前只写一次预览副本；批准后才另行写权威存档。

## 通道判定

从真人指定的通道种子开始，只做局部分析：

- 脚下必须有连续承重面，脚位和头部净空连续；
- 局部 flood-fill 后骨架化为中心线，每两格采样一次断面；
- 记录净宽、净高、地板、墙、窗、栏杆、支撑和材料；
- 门平面、楼梯首级、电梯层门、岔路或已命名地点才允许成为端口；
- 裁剪边缘只能标 `UNKNOWN`，不能当出口；
- 窗和栏杆不能当入口；装饰楼梯不能当楼层连接；
- 电梯必须有连续井道和两侧层门；楼梯必须连接不同 Y 层；
- 新段默认继承相邻通道中心线、净宽和净高。

端点未知、法向未知、无支撑、触及 `HARD/HOLD`、或在扫描边缘终止时立即
`NO-BUILD`。

## 写入协议

每格写入必须同时满足：

```text
坐标属于 positiveEditMask
当前完整方块状态/NBT 等于预览时记录的旧状态
坐标不属于 HARD/HOLD
补丁内存在该格的 inversePatch
```

人工修改登记为 `owner=human`。如果当前状态已不在实测允许集合里，说明真人改过，
运行时生成器必须跳过；世界本身就是记录。

每次只刷新补丁 bbox 外扩两格内的局部语义图。禁止每轮重算全世界哈希、全图连通、
全局支撑或自动寻找“可建房间”。只有基线建立或明确诊断时才运行全局工具。

## 工具与模型分工

- `query_blocks.py`：所有局部方块实测和 ASCII 图；首选。
- `survey_facility_target.py`：只在需要视觉空间证据时生成局部证据板和 GLB。
- `facility_map.py` / `facility_audit.py`：只产出候选证据，绝不赋予语义或写入许可。
- GPT-5.6 Pro：整理原作约束和地点语义，解决语义冲突。
- Codex：确定性读取、证据生成、局部 diff、可逆补丁和批准后的执行。
- Claude/视觉模型：独立看证据，提出异议；不修改世界或地点身份。
- 真人：唯一的地点命名、端口确认、审美批准和权威存档写入授权者。

禁止并行决定地点身份、端口连接和世界写入。单一事实源应是
`spatial_twin.json` 与 patch journal，而不是无限增长的工作日志。

## 开销纪律

- 不再逐轮读取或追加 `.Codex/ACTIVE_WORKLOG.md`；历史只在考古时读。
- 活跃约束放在本文件、相关源码注释或不超过 200 行的短决策清单里。
- 不为一次查询新建数百行脚本；优先使用 `query_blocks.py` 或十几行内联调用。
- 不靠试错寻找已经存在于源码、NBT、字节码或真人作品里的参数。
- 分不清时先输出 ASCII 剖面或证据板，停止写入。
- 只在真人批准前拷一次预览副本；写冻结存档前导出局部还原快照。
