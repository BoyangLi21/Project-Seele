# R24 原生渲染与车辆性能记录

默认仍是 **24 区块真实地形、8 区块模拟距离、6 GB 客户端堆**，使用独立显卡。没有重新启用此前出现透视问题的 Distant Horizons／Acedium。服务器负责世界模拟与加载；客户端还要接收区块、更新本地实体并绘制画面，不能把这些成本全部转移到服务器。

本轮测试机器使用 NVIDIA GeForce RTX 3070 Ti Laptop GPU。以下是预热后固定视角的帧时间，不是整段驾驶或航班的帧率保证。

| 视角 | 中位帧时间 | P95 帧时间 |
|---|---:|---:|
| 城市远景 | 11.91 ms | 38.09 ms |
| 地下金字塔 | 16.42 ms | 31.00 ms |
| 地下湖岸 | 8.43 ms | 12.53 ms |
| 大指挥室 | 8.59 ms | 13.96 ms |
| UN 基地，车辆优化后的最终复测 | 62.61 ms | 159.82 ms |

**UN 基地仍是明显的性能瓶颈**。不能把城市视角的结果套用到密集战备区域，也不能把本轮固定机位测试当成 F2 全航程没有加载停顿的证明。R23 的高速航班加载停顿记录仍然保留。

## 保留的等值优化

- 深区块的天空光初始化跳过已证明透明的区段。71,424 个逐列结果与原算法一致；实际区块初始化的该函数采样约快 2.20 倍。这不是整机 FPS 提升倍数。
- SBW 普通静态方块使用相同的完整／空碰撞形状；自定义机械、门、液体等仍走原逻辑。
- 对 UN 停稳、无人驾驶且环境不变的车辆复用原生零位移结果。位置、姿态、旋转包围盒、单次地面探测模式、区块变化与标签更新都参与失效判断；检测范围覆盖翼展。10 种车辆、60 组移动向量以及 13 项登车／移动／改地面等检查通过。
- 远距离渲染副本收到完全相同的数据时，避免重复重建整份车辆状态。真实世界中的实体不走这一分支；位置、姿态、弹药、时间戳和声音的原数据包处理仍执行。56,220 次完整原生处理回放的状态与插值字段比较一致。

开发回退开关分别是 `projectseele.vanillaSkyScan`、`projectseele.vanillaVehicleShapes`、`projectseele.vanillaVehicleRest` 和 `projectseele.vanillaPhantomLoads`。这些是排查用 JVM 参数，不需要普通玩家逐项设置。

## 没有设为默认的遮挡试验

参考 [EntityCulling 原作者说明](https://github.com/tr7zw/EntityCulling)，单独试验了只跳过遮挡绘制的配置：关闭实体逻辑跳过、关闭方块实体剔除，将本项目全部 24 类实体列入白名单，并保持驾驶中或移动中的车辆可见。

1.10.5 与 1.8.0 的内嵌 UI 依赖在当前 ForgeGradle 开发映射下无法加载；未把失败的启动当作测试通过。自包含的 1.7.3 可以运行。在同一 JVM、同一机位进行关闭／开启／关闭／开启的四段对照后，中位帧时间分别为 53.66／54.93／58.90／53.32 ms，没有确认稳定的大幅收益，因此**没有纳入普通启动器的默认配置**。

本机原始测量、JFR、碰撞对照和开关截图保存在 `artifacts/facility_r24/validation` 与 `far_native_*`。启动和加载尖峰单列记录；用于诊断的采样分析器不在正常帧率测量时开启。官方模组仅从原下载地址取得并校验 SHA-512，二进制不随源码重新分发。
