# R31：UN 复位与落地插入栓

本次修复保留正常复位时两台机体与插入栓的原 UUID。只有已经弹出、落地、无人乘坐并且被攻击销毁的插入栓，才允许在机库补充新栓。

## 修改依据

- 原 UN 停靠位置使用 `UNHomeYaw`，旋转却读取实时机体朝向。现在两者都使用机库固定朝向。按照现有十格长栓体与 15° 停靠角推导，90° 的旧朝向差可让栓尖偏移约 7.63 格，同时舱口操作标记还在原点；这是源码几何推导，不是游戏实测。
- 插入栓原有位姿回调改了 `xo/yo/zo`，实体渲染器采用的却是 `xOld/yOld/zOld`。现在外壳和舱内摄像机共用 canonical 位姿流；复位额外发送硬边界，清除位置、朝向历史，即使两次复位坐标完全相同也会生效。
- 机械版本或 UN 机型改变时，在 Gecko 求值之前清除该实体的骨快照与控制器，恢复完整骨架绑定姿态，再执行新的动画。UN 手部、蹲射、飞行与关机姿态缓存一并失效，不清空其他机体状态。
- UN01 的实机复位还暴露了臂部 IK 坐标基准错误：源几何的肩、肘、腕绑定旋转为零，但旧求解器用 X 轴作为所有机体的肘弯基准；两台 UN 的实际绑定弯曲面法线是 Z。待机躯干仅倾斜 2° 就会让几乎为零的半球符号测试换边。现在仅带实测 `r30_elbow_socket` 的 UN 臂使用实际 `上臂向量 × 前臂向量`，同时作为方向半球参考和旋转源基准；NERV、使徒及腿部求解路径保持原实现。Gecko 4.8.4 的初始快照已是运行时角度，不能再反转 X/Y。
- 首次重新进入视距时，客户端局部姿态时钟从当前同步数据重建，保留已经收到的趴姿、持枪等状态；机械 reset 同时清除客户端受击与抓投姿态缓存。
- 复位统一清机体的当前/前一帧朝向，并让直接乘坐的玩家和训练驾驶员正常离开。维修先恢复血量，再进入机库待机，避免零血残骸状态进入下一次启动。
- 落地空栓可用近身攻击或武器销毁；普通玩家攻击可见尾端时按真实栓体 OBB 做三格射线，不会因实体原点在十格外的尖端而打不到。服务端重新检查距离、阶段、乘员与墙体遮挡。机库栓、运输中栓、插入中栓、有人栓均不能用此功能销毁。
- 已确认毁损写入世界 SavedData 墓碑。UN 机体回到机库后补充备栓；找不到一个仅仅卸载的原栓不构成补充许可。

## 人工验收步骤与扩展场景

1. 同时观察 UN00 与 UN01，记录 UUID；分别完成蹲/趴、持枪、UN01 飞行后执行 `/seele military reset 00` 与 `/seele military reset 01`，每台重复两次。检查手腿/喷口恢复待机，原 UUID 不变，栓体与舱口都停在吊机下，另一台不受影响。
2. 复位后直接重新登机、插入、走出机库；再重进世界执行一次复位，检查旧骨快照、运输与飞行状态没有回来。
3. 地表按 V 弹出。飞行途中、乘员尚在时尝试攻击应无效。落地离舱后从尖端和尾端近身攻击各测试一次；一个销毁后机库应只补一支备栓，机体 UUID 不变，再次登机可用。
4. 原栓仍存在但所在区块卸载时执行复位，必须加载并召回原栓；不生成备栓。隔墙尝试攻击落地栓也应无效。

统一原生检查已完成两台原 UN 的登机、蹲、趴、持枪与 reset，确认两台原机体和原插入栓 UUID 保留、复位后骨骼和显示位置正常；使用实际左键清除独立落地空栓，同时确认载人和机库栓不会被清除。证据位于 `artifacts/facility_r31/native_mechanics_1790135928886/`。以上飞行后复位、隔墙攻击等扩展场景未全部在此检查中执行，仍保留人工验收步骤。空运的客户端栓体对齐另行检查，不能据这份 reset 结果认定运输画面已通过。
