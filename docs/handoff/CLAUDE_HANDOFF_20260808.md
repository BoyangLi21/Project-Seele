## 1. 本轮改了什么

### 1.1 城市大屏（后墙 z=362 黑面）

| 项 | 旧 | 新 | 依据 |
|---|---|---|---|
| `see_through` | true | **false** | 开着等于关深度测试，字会穿透屏幕和墙 |
| 缩放 | 2.0 → 5.0 → | **4.5** | 见下 |
| 位置 | (28,−430,361.38) | **(28,−434.18,361.55)** | 见下 |
| 行数 | 10（未变） | 10，每行 ≤36 列并截断 | 超出会跑到檐口上 |
| 开关 | 无 | 第 5 块屏，按钮 (28,**−409,289**) | |

**锚点规则（反编译 1.20.1 `DisplayRenderer$TextDisplayRenderer` 得到，不是猜的）：**

```
matrix4f.rotate(PI, 0,1,0);
matrix4f.scale(-0.025f, -0.025f, -0.025f);
matrix4f.translate(1 - width/2, -lines*10, 0);
```

→ **文字框的底边落在实体坐标上，整块往上长**，不是居中。
→ 世界高度 = `0.025 × (行数×10 + 1) × 缩放`。

实测显示面：`x 9..47, y −435..−423` 连续黑混凝土（y=−436/−422 只有 30/39 格，
被橙块和海晶灯打断，不算）。换算世界坐标 x 9..48 / y −435..−422。
代码里 `cityStatusBaseY()` 用这四个边界 + 行数**算**位置，改行数或缩放会自动重算。
当前：块高 11.36 格，上下各留 0.82 格。

正前方 5 格全空气，**没有玻璃**——所以关掉 see-through 不会挡住任何东西。

### 1.2 下方橙色战术屏

原来是 `ensureTacticalTexture()` 画的一张**静态贴图**，从不含任何数据。

现在：服务端每 20 tick 采样三台 canonical EVA → 新包
`ClientboundPilotStatusPacket` → `PacketDistributor.DIMENSION` 推给 GeoFront 全体
→ 客户端在同一斜面上画字。显示 phase / 驾驶员 / 同步率 / AT 场 / 供电（外部脐带
或内部剩余 mm:ss）/ 血量 / 画面 LIVE·STBY / 暴走。

**为什么不在客户端扫实体**：机库里的 EVA 经常在指挥室玩家的实体追踪范围外，
正好是发射时最需要看的时候会空屏。

倾角 `S20_LOWER_SCREEN_PITCH` **−68.8° → −61.8°**（立起 7°，真人要求）。
改之前采样确认：板面全长 41 格已是空气（假屏方块被 `install()` 清过），
法线前后各 4 格也空，7° 偏移 ±2.47 格落在空腔内，不会插墙。

**斜面文字的变换（容易翻车，记下来）**：光栅面是 `yaw(180)·pitch(p)`。
文字**不能**用同一个变换加镜像缩放——镜像会翻转绕序，`RenderType.text` 的背面
剔除会把所有字剔光。正确做法是把 yaw 共轭掉，只剩一个反向 X 旋转：

```java
poseStack.mulPose(Axis.XP.rotationDegrees(-pitch));
poseStack.translate(0, 0, -0.03);      // 局部 -Z = 朝观察者
poseStack.scale(-s, -s, s);            // det = +1
```

数值验过：text +x = 屏幕右、+y = 屏幕下、+z = 屏幕内，det = +1，与光栅面共面。

## 6. 方法笔记（这轮真正起作用的东西）

1. **不要从方块反推语义，从权威数据取规格。**
   文字锚点从字节码取，不从试错取；椅子模板从真人认可的那格取，不从调色板猜；
   朝向从靠背方位反推，不假设。
2. **量准 ≠ 看懂。** 我能精确说出 z=362 在 −397 以下实心、−396/−395 是空的，
   但分不出那是设计的凹缝还是破损。分不清就停手并把图摆出来问，别填。
3. **每一条改动都要有坐标锚点。** 本轮五件事全部落地，唯一原因是真人给了坐标。
   "把通道全连通"这种任务我做不了，之前也确实没做成。
4. **写入冻结存档前先存还原快照。** 561 行 setblock，几十行脚本的事。
