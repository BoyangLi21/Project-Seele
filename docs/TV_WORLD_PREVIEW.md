# TV 地形与都市重塑预览

本机独立存档：`SEELE_TV_WORLD_PREVIEW_20260906`，显示名
`SEELE - TV World Reconstruction Preview`。入口为
`tools/start_tv_world_preview.bat`。本轮已到人工验收点，未替换原 R28 或已认可的 TV 内饰源档。

## 本轮布局

- 使用已批准的新种子 `-3816295015381828007`，城区接自然地表，海岸在东侧。
- GeoFront 改为宽浅穹顶：半径 1800 格、中央平顶半径 600 格、顶面 Y=24，
  地面约 Y=-478；按现有设施尺度适配原 TV 的空间比例，并非逐米复制。
- 湖在总部西侧，森林呈片状分布。总部地基与周边地面接合；修正迁移范围遗漏的
  金字塔西、南外壳。保留原存档已认可的 TV 内饰、机库、人员电梯和三条发射线。
- 93 栋原创升降楼采用六组灰白装甲立面和不同高度；保留三栋本机已有外部建筑。
  这些建筑使用原有升降控制，移动后的顶部位置适配新的中央平顶。
- 指挥室、EVA 和电梯的坐标变换为零，避免改变既有控制器、门和路线绑定。

已有私有素材及存档不进入 Git 或发布包；新增立面由项目代码生成。

## 扫描与人工检查

按负责人本轮建议，以方块扫描作为空间检查的主要手段，避免客户端区块渲染截断
造成误判。工具 `tools/scan_tv_world_preview.py` 只通过 `query_blocks.py` 读取。
输出位于 `artifacts/tv_world_preview_20260906/scans/`；粉色表示未测得的区域，
不能解释为空地。俯视图是逐列抽样，局部剖面为逐格读取。

人工验收重点：城市和海岸的比例、金字塔完整轮廓、湖岸与森林层次、真实光照和
材质观感。扫描能确认几何与连接，不能代替这些视觉判断。

自动验证已确认：93+3 栋楼完整下沉与复位、所有外部楼体附件保留、火把掉落为零；
在一层楼体尚未移动完时反向操作，136,212 个屋顶采样格保持不变，最后完整复位。
三台 EVA 均以原 UUID 连续完成登机、出击和回收；最大逐 tick 位移为 5.604 格，
未使用跨维度或整段传送。重新加载后三台机体、三具插入栓和三名训练驾驶员仍各一份。
五组人员电梯的 14 趟实际载客往返通过，覆盖全部楼层、完整轿厢地板/顶板和到站门口净空；
地表电梯上下行跨越 523 格。最终 `gradlew --offline build` 和客户端验证均通过。

默认验收起点为地表电梯亭外 `(112.5, 81, 273.5)`。已生成 2,688 个核心区块及
1,056 个东侧海岸区块；更远区域会随探索按同一生成规则继续展开。最终扫描的城区
东侧可见连续海湾，总部西侧为地下湖。

本轮同时修正了实体加载就绪判定、外部楼宇逐行更新造成的大量火把掉落、清理误删
当前楼体标记，以及移动途中维护误删屋顶的问题。原作风格是否达到预期仍留给人工裁决。

## 本机恢复与复现

原 `SEELE_S20_RECOVERY_R28` 和已认可的 `SEELE_PYRAMID_TV_PREVIEW_20260905`
仍作为独立源存档保存。本轮只编辑新预览。源存档 SHA-256 清单、区域备份、逐格
正反补丁及运行记录位于 `artifacts/tv_world_preview_20260906/`。

重建流程依次为：新存档元数据及专用数据包 → 新地形生成 → 已测量设施体积 →
实体/运行存据迁移 → 都市与植被整理 → 完整金字塔外壳和地基 → 运行验证。
相关工具均拒绝覆盖已经标记交付的存档；不要在 Minecraft 占用存档时执行离线写入。

专用数据包必须随存档保留。仅修改 `level.dat` 的生成器参数会被 Minecraft
启动时重建的维度注册表覆盖。其他旧存档不启用 `tv_preview`，继续使用原生成方式。
