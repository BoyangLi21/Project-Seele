# R30 UN 双机资源

两台机体使用本轮取得的 Lux3D 原始网格，继续在本地加工。UN-00 保持黑色装甲、金色边线与单眼光学系统；UN-01 保持绿色装甲、蓝色柔性部位、红色五角星和 UN 识别，背部安装可偏转喷口。没有重新压缩体宽来强套初号机骨架。

## 几何和材质

- 各自独立骨架与实测肩、肘、膝、腕位置；两手各五指，四指三节、拇指两节。
- 按网格表面的连通距离分区，避免仅按横坐标划分时将宽机体的大腿错误挂在手臂上。
- 重新制作眼部、手部、背部插入栓开口与活动盖、UN 标记、装甲边条和喷口。关键装甲另加拟合曲面的金属面板，减少生成底模表面起伏。
- 每台配套 4096×4096 基色、粗糙度/金属度、LabPBR 与发光贴图。平法线贴图不包含虚构的细节；曲面法线来自实际几何。
- 眼部发光层背景保持透明，避免光影下把整个头部盖黑。使用 Complementary 的 LabPBR 模式。

高面数和 4K 贴图不等于影视资产等级。模型仍以生成底模为基础，保留可编辑源文件，供后续进一步手工拓扑与造型精修。

## 驾驶接入

游戏中的两台原机体与原插入栓身份保持不变。模型包、服务器端人体测量数据及背部机械轮廓一起更新。握枪使用各自手臂长度与掌心坐标；趴下过渡时，只在地面进入手臂可达范围后才让左手离开枪身支撑。

UN-01 喷口随悬停与前飞偏转，尾焰位置使用同一喷口变换。核能、运输净空、自动落地和原机回收入库仍使用真实游戏逻辑。

运输碰撞按每个部件的分层包围盒检查，避免把肩宽错误地当作胸背厚度而卡住原登机廊。UN-01 喷口安装位置避开登机廊，并在地面收起。双机吊升和近库路径各 79 个位置，已对当前存档的 6,025 格实体结构作离线相交检查；实际回库结果另以原生测试为准。

刚性装甲在普通渲染与 Oculus 光影下均使用显卡顶点缓存；柔性关节保留原来的蒙皮变形路径。没有修改作者的光影 ZIP。

## 可复现文件

本地工作目录为 `artifacts/facility_r30/models`；原始任务文件为 `artifacts/facility_r30/lux3d/un00` 和 `un01`。生成任务分别为 `3672326`、`3672329`，没有为本地建模伪造新的云端任务。

主要工具：`build_un_airframes_r30.py`、`finish_un_details_r30.py`、`bake_un_materials_r30.py`、`stage_un_models_r30.py`、`render_un_r30.py`、`export_un_models_r30.py`。修改后的 `.blend` 保留骨架与材质；`.glb` 提供可导入的静止完整骨架，实际游戏动作由 Minecraft 运行时代码驱动。GLB 使用标准线性蒙皮，游戏与 Blender 编辑场景的关节保体积算法有所不同。

生成网格、参考图和第三方私人资源不随开源代码提交。当地最终交付清单记录文件散列、原生驾驶证明和预览验证范围。
