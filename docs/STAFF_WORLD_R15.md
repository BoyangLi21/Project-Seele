# R15：人员、战斗收尾与远景

本轮作用于 `SEELE_TV_WORLD_PREVIEW_20260906`。原始模型、存档和第三方动捕仍留在本地；公开提交包含运行代码、原创人员皮肤、工具和记录。

## 工作人员与指挥

当前名单配置 **228 个岗位：地下 160、UN 基地 68**，地面两座城市不生成居民。人员随玩家访问和区块加载出现，初次每秒最多生成四人；平时关闭寻路，执行指令时才移动。观察模式也会触发岗位加载。每个岗位绑定一个持久 UUID，区块卸载不会触发补刷。

指挥台放置葛城美里、赤木律子、伊吹摩耶、日向诚和青叶茂。其余岗位覆盖科研、医疗、保障、机库、交通端点和基地安保。九套 64×64 角色与制服皮肤由本轮代码原创绘制；网络皮肤页面已查阅，但下载没有成功，因此没有把网络皮肤当作已安装素材。

右键工作人员可以看到台词和可点击的对话选项。美里、律子支持：

```text
/nerv talk misato 整备 01
/nerv talk ritsuko 回收 01
/nerv talk misato 发射 01
/nerv talk misato 停止操作
```

需持 NERV 通行证或具有操作员权限，并在工作人员身边下令。系统只接受明确的一项操作与一台机体；否定句、询问句、混合机号不会触发动作。这是离线的固定指令对话，不依赖语言模型服务。

工作人员先加载对应机体的状态，沿真实路径走到控制台，按下实际按钮，再调用现有权威控制流程。发射仍要求驾驶员、插入栓、供电、轨道等联锁成立。对话不会把“按键已操作”说成“发射已成功”。已执行的操作不回滚；尚未执行的操作可由下令人或管理员取消。断线、离开、权限丢失和超时会中止待办；重载不会重新按键。

三个 DUMMY 驾驶员增加了不同语气的短台词，并报告待命、登机或连接状态。

## 战斗动作

重做了最后一次打击之后的反冲、起身、两步接近和锁臂过程。使徒先完成站位，再合拢手臂；上一版改变体形的包覆顶点变形已停用。初号机右肘在切换点的一次大幅跳变也已去除。镜头重新覆盖接近过程，保持原有 460 tick 的演出时钟和胜利、跳过、恢复驾驶逻辑。

这是参考 TV 第 2 话顺序制作的游戏演出改编，包含动捕基础和手工接触约束。最终连续区间 16.3–18.6 秒按 60 Hz 检查了 139 个真实网格样本，双方三角形交叉为零；关节最大相邻帧转角为初号机 22.11°、使徒 24.58°。原生游戏播放、跳过、中断和重载等 18 项检查通过。

验收视频位于 `artifacts/staff_world_r15/review/eva_sachiel_r15.mp4`，约 5.25 MB。图像来自游戏帧缓冲，没有插帧；声音是按实际演出时刻离线混合的原创合成音效，不是电视剧音轨或游戏实录音轨。

## 地图与门

本轮在已命名房间中替换 5,623 个粗石饰面方块，在地下西侧林地补充 4,533 处林下覆盖、在东京西侧边缘补充 471 处细节。地形标高保持不变，种植区与工程结构保留 12 格间隔。所有修改经过冷备份、逐格前置检查和回读。

人员通道门、人员电梯门和机库压力门使用统一的金属分缝、识别条、边框与状态细节。既有机械控制和门洞保持原有职责。

检查发现旧电梯按地板材质识别轿厢，饰面替换会触发误重建。已为新材料补上识别，并从修改前的精确备份恢复原有轿厢和两个选择器方块实体的数据。另修复了指挥室后方电梯在服务器卡顿时的乘客位置漂移；五段实际载客检查通过，最终返回原来的 Y=-419，最大单 tick 位移 1.3 格，轿厢地板、屋顶与出口全部核对。

本轮原生复查 201 条相关通行路线，完整目录恢复为 8,550 条。其余路线沿用 R14 的验证，不重复计为本轮测试。大指挥室按材料等价核对静态布局；2,344 块单向窗、钢琴书本和原有三台 EVA、31 个军事对象、84 个工业对象的身份均作了保留检查。

## 低配与服务器

可选入口是 `tools/start_low_end_r15.bat`。它使用当前正式存档，验证固定版本依赖，应用低配配置，并在退出时恢复之前的选项。

| 项目 | 低配预设 |
| --- | --- |
| Java 堆 | 1–4 GB |
| 完整方块距离 | 4 区块 |
| 模拟距离 | 5 区块 |
| 远景半径 | 96 区块 |
| 帧率上限 | 60 |
| 驾驶光学直播 | 640 像素宽、10 FPS、128 KiB 帧预算 |
| 近处 EVA | 使用现有详细模型 |

使用固定版本 Distant Horizons 3.2.0-b、Embeddium 0.3.31 和 FerriteCore 6.0.1。默认普通启动方式继续可用。Distant Horizons 可以由服务端生成、发送远景；本轮也验证了其专用服务器加载。[Distant Horizons 官方说明](https://modrinth.com/mod/distanthorizons)、[Embeddium 官方说明](https://modrinth.com/mod/embeddium)。

GeoFront 必须关闭洞穴剔除，采用较高垂直细节，并忽略人工天空层。早期测试中的悬空条带来自未完整生成的缓存；实际启用集成服务端生成、补齐已有区块后，城市与地下金字塔均恢复连续显示。生成模式为 `PRE_EXISTING_ONLY`，不会扩张新地形。

首次缓存适合在配置较高的电脑或服务器上准备。普通低配预设只用少量后台资源补齐；未来迁移时让服务器承担生成工作。地形与建筑的远景不会扩大各模组对人物、车辆等动态实体的可见距离。

本机 RTX 3070 Ti Laptop 的四个固定视角测试使用 4 GB 堆，60 FPS 上限下中位帧时约 16.7 ms、95 分位约 19–21 ms，观测堆使用约 1.8–3.1 GB。这是本机兼容性与预算验证，不等同于所有低配电脑的帧率。

服务器打包脚本已切换到当前世界，并补齐 SBW、Kotlin 等依赖；默认服务器堆 2–8 GB、视距 6、模拟距离 5。迁移时要保留 `regional_plan.json`、人员名单、`data/` 和各维度 `entities/`。漏掉区域迁移元数据会把控制器指向旧机库；只迁移地形也会丢失人员身份。详见 [私人服务器部署说明](PRIVATE_SERVER_DEPLOYMENT_CN.md)。
